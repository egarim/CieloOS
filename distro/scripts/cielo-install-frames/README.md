# Install screen frames

Pre-rendered frames for `cielo-install-tui.sh`, the animated install screen.
Nine stages, one per `==> [n/9]` step in `distro/install.sh`, twelve frames each.
The picture is a diagram of CieloOS assembling itself: each step reveals the box
it actually installs, so the animation *is* the progress indicator rather than a
decoration running beside one.

```
stage-1.ans   ubuntu · dependencies        the foundation bar
stage-2.ans   + podman
stage-3.ans   + session images, search
stage-4.ans   + restart policy
stage-5.ans   + /opt/cielo runtime         and the tree down to the base row
stage-6.ans   + environment line           mode/bind, overlaid at runtime
stage-7.ans   + cielo-runtime.service
stage-8.ans   + chat, panel
stage-9.ans   + presentation mode crown
```

Each file holds its twelve frames separated by a form feed, so the player loads a
whole stage with one `mapfile -d $'\f'`. Colours are 256-colour SGR, not
truecolor: a kiosk or headless install draws on the Linux virtual console, which
understands `\e[38;5;Nm` and does not understand truecolor.

## Regenerating

The frames are generated by [ASCII Motion](https://github.com/CameronFoxly/Ascii-Motion).
`src/cielo-install.mjs` holds the layout — box positions, labels, which step
reveals what — and renders every frame; `src/export-ansi.mjs` turns those into
the `.ans` files here.

```bash
cd src
node export-ansi.mjs ..        # rewrite the .ans files
node preview.mjs 5 9           # eyeball a stage as plain text
```

Neither needs anything installed. To edit the frames by hand in the ASCII Motion
editor instead, run `node cielo-install.mjs` with an `ascii-motion-mcp --live`
bridge up — it pushes all 108 frames into the editor as one timeline.

Changing a label or a box position means editing `src/cielo-install.mjs` and
re-running the export; the `.ans` files are build output and should not be edited
directly.
